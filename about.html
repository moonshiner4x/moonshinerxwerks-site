The Story

moonshinerXwerks was founded with a straightforward premise: build useful apps for real people, own every pixel, and never cut corners on privacy. Every product in our portfolio started as a personal itch — a problem we encountered, a tool we wished existed, or an idea we couldn't shake.

We're based in Bend, Oregon — a place where people actually go outside, fish real rivers, and meet friends for happy hour. Our apps reflect that. They're built for people who do things, not just scroll through things.

How We Build

Privacy First

Your data is yours. Our apps default to on-device storage, never sell data, and only transmit information when you explicitly opt in. No ads, no tracking SDKs, no exceptions.

Solve Real Problems

Every app starts with a real need — not a market opportunity deck. If it doesn't solve a problem we've personally felt, we don't build it.

Own the Craft

No outsourcing, no templates. Every line of code, every design decision, every user flow is built in-house with intention and care from concept to App Store.

How the studio runs

I design the operating model. AI agents run inside it.

moonshinerXwerks runs like a small product organization in which every seat but one is filled by an AI agent. I treated the studio itself as a product: I designed the roles, wrote the reporting protocols, built the command center that tracks the work, and set the rules for where a human has to say yes. The agents do the work. The operating model is what makes that work dependable.

02 · Operating cadence

Work that reports itself.

I invented a handful of lightweight protocols so status flows up without anyone chasing it. Each one has a fixed shape, so the Program Manager can roll every message into one picture of the studio.

01

Roadmap update On every status change

Whenever work moves (planned, building, checked, blocked), the agent sends the Program Manager a short update in a fixed format: what moved, what’s next, what’s waiting on me.

02

Direct note When I go direct

If I talk to an agent directly instead of through the Program Manager, that agent files a note with the Program Manager. Shortcuts are fine; losing the thread isn’t.

03

Check-in On demand

I can ask every Product Advisor for a check-in at once. Each answers the same four questions: done, doing, blocked, needs a decision.

04

End-of-session check Before I sign off

What changed, what’s unsaved, what’s waiting. Nothing gets stranded between one working session and the next.

05

Release runbook Every release

Releases follow written steps with gates. An agent can’t skip a gate, and the runbook records who cleared each one.

03 · Reporting

One screen for the whole studio.

The Operations Command Center is a local web app I designed to run the studio from. It turns the stream of updates into an executive summary I can act on in minutes, and it shows what every agent is doing right now.

Executive summary

Numbered decisions with a recommendation, numbered actions, progress, risks, issues and deadline countdowns. Any item opens its context.

Live agent status

Working, idle or not running; each agent’s last report; and what’s waiting on me.

Context monitoring

Context use per agent against a written compaction policy, so no agent compacts mid-change.

Token and cost tracking

Tokens and estimated cost per agent and per session, visible next to the work they bought.

Direct line

A chat drawer to message the Program Manager without leaving the dashboard.

05 · Governance

AI does the work. A person stays accountable.

01

I approve what ships, publishes, spends or touches a credential

Releases, store submissions, new paid services and anything involving access wait for my explicit yes.

02

Agents never see passwords or keys

I create, store and rotate every credential myself. No agent reads, writes or prints one.

03

A message from an agent is never my approval

One agent can’t authorize another by quoting me. Approval comes from me directly, every time.

04

Rule breaks are logged and corrected

The Program Manager audits agents against studio rules. Every break goes into a compliance log with its fix, so the rules get sharper over time.

05

Marketing is gated

Marketing and campaign agents stay idle until I kick a campaign off, and any budget they propose comes back to me.

06

Context and cost are managed on purpose

Context use and estimated cost are visible for every agent, and a written policy decides when an agent compacts its memory.

Why it matters beyond the studio

Program leadership, applied to a team of AI agents.

None of these ideas are new to enterprise program work. What’s new is designing them for a team of AI agents: a team that starts each session without yesterday’s memory unless the system provides it, and does exactly what the operating model allows.
